## One case where an agent was wrong, and how I saw it

In Phase 1 the test-writer wrote `INV01_request_has_no_way_to_change_the_discount` as a reflection
test over every public method of the aggregate, asserting that no instance method takes an `int`.
It could never pass for any Java class: `Object.wait(long, int)` is inherited by everything. I saw it
because the failure message listed the parameter types it found, and the list ended with
`Object, long, long, int`, which are exactly `equals`, `wait(long)` and `wait(long, int)`. The
implementer did not change the test to make it pass; the test-writer was asked to fix its own test,
confirmed the mistake, and excluded methods declared by `Object`. The rule "never change a test to
make it pass" plus a failure message that names what it found is what made the mistake visible.

Other cases are in the phase lines above: the Phase 2 attack asked for two contradictory
behaviours (a backwards clock must stay readable, and decreasing timestamps must be rejected); the
Phase 3 attack argued against the documented check order four times; the Phase 8 reviewer flagged
the API version header as wrong from memory, while the value came from the current API reference.
