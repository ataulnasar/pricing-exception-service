# ADR-004: Optimistic locking with ETag and If-Match

**Status:** Accepted

## Context

Two reviewers may try to decide the same request at the same time. Only one may win (INV-05).
A client with an old view must not overwrite a newer change.

## Decision

- Each request has a version (JPA `@Version`).
- Create and read return `ETag` with the version in double quotes, for example `"0"`.
- Decision, withdrawal and supersede need `If-Match` with that exact value.
- No `If-Match` returns `428 IF_MATCH_REQUIRED`.
- An old version returns `412 VERSION_MISMATCH`.
- A lost race inside the transaction returns `409 CONCURRENT_MODIFICATION`.
- `*`, weak tags, lists and unquoted numbers return `400 MALFORMED_REQUEST`.

## Consequences

Good:
- No lost updates.
- No database lock is held between two HTTP calls.

Bad:
- A client must read the `ETag` before it decides, withdraws or supersedes.
- A client must read again and retry after a `412`.

- `WorkflowIT.INV05_decision_without_if_match_is_428_end_to_end`
- `ConcurrencyIT.INV05_two_parallel_decisions_only_one_wins`
