# ADR-005: A separate approved-discount endpoint for the mortgage process

**Status:** Accepted

## Context

The mortgage application process needs one discount, and who approved it and when. It should
not read the whole request history to find that.

## Decision

`GET /api/applications/{id}/approved-discount` returns `applicationId`, `discountBps`,
`requestId`, `decidedBy` and `decidedAt`. Only the `MORTGAGE_PROCESS` role may call it. Other
roles get `403 WRONG_ROLE`. An unknown application gets `404 APPLICATION_NOT_FOUND`. An
application with no APPROVED request gets `404 NO_APPROVED_DISCOUNT`.

## Consequences

Good:
- A small contract with one role allowed.
- The mortgage process does not need the full request model.

Bad:
- It is a second read path that must stay correct.
- The mortgage process must treat `404 NO_APPROVED_DISCOUNT` as "no discount".

## Proved by

- `SupersedeIT.approved_discount_lifecycle_404_before_200_after`
- `SupersedeIT.approved_discount_other_roles_are_403_WRONG_ROLE`
