# ADR-001: Requests never change; the RM supersedes instead

**Status:** Accepted

## Context

One stakeholder wants RMs to change the discount after submit. Another wants an approval to
always apply to the exact request that was reviewed. Both cannot be true if a request can be
edited. See R7 in `docs/requirements.md`.

## Decision

A submitted request never changes (INV-01, `docs/invariants.yaml`). To use a different discount,
the RM supersedes a PENDING request. In one transaction, the old request becomes SUPERSEDED and a
new PENDING request is created with `supersedesId` set to the old one. An approval stores
`approvedDiscountBps`, the discount the reviewer saw.

## Consequences

Good:
- An approval always applies to the request that was reviewed.
- The history shows every discount that was asked for, and who asked.

Bad:
- To change terms, the RM creates a new request, and a reviewer must review it again.
- Only a PENDING request can be superseded. After an approval, the discount cannot change.
- An APPROVED request keeps the application's single active slot (INV-04). After an approval, no new
  request and no supersede is possible for that application.
- Every supersede adds rows.

## Proved by

- `PricingExceptionServiceTest.INV01_approval_records_reviewed_discount`
- `SupersedeIT.INV01_only_pending_request_can_be_superseded`
- `SupersedeIT.INV01_no_endpoint_changes_discount_after_approval`
